# Local face detection inference

The inference crate runs a pinned face detection ONNX model through the bundled ONNX Runtime library. The macOS and Windows apps package the RetinaFace MobileNet0.25 model (`assets/model/face_detection_retinaface_mb025.onnx`). The pinned OpenCV Zoo YuNet model is not packaged on either platform; it remains only as the benchmark baseline (on Windows the DirectML build of the runtime, which also runs the CPU provider). Both models have a fixed 640×640 input. Frames remain in memory for one call; the detector returns only presence, confidence, or an insufficient-light status.

`runtime/macos-arm64/libonnxruntime.dylib` is the arm64 macOS runtime used by tests and packaged builds. Recreate it from Microsoft's pinned official release with `./tools/inference/fetch-macos-runtime.sh`. The script downloads only when explicitly run and verifies both archive and library checksums. No runtime download occurs in the application.

Before signing a macOS app, copy the verified assets into its bundle with `python3 tools/inference/prepare.py --resources-dir MyApp.app/Contents/Resources --frameworks-dir MyApp.app/Contents/Frameworks`.

The native shell resolves both absolute bundle paths and passes them to `tv_inference_create`; the C ABI is defined in `include/telaviva_inference.h`. For light recovery, `tv_inference_assess_light_bgra` checks illumination without initializing or running the model. The macOS shell still creates CPU sessions. `tv_inference_create_with_provider` accepts a CoreML candidate; unavailable or failed CoreML session setup falls back to CPU, and the selected candidate can be queried per handle. On Windows the shell chooses the device from the `inference_device` setting (see `api.md`, section inference-device-selection) and the package ships the DirectML build of ONNX Runtime as its only `onnxruntime.dll`: fetch it with `powershell -File tools/inference/fetch-windows-runtime.ps1 -Variant directml`. `-Variant cpu` (the default) installs the CPU build, which is not packaged; only the Windows CPU-runtime tests use it, when it is present; the Rust Windows smoke test reads the DirectML runtime. Runtime provider availability does not establish an energy benefit.

Run inference crate checks with `cargo test -p telaviva-inference --all-targets --locked`. The integration test loads the actual bundled runtime and model, checks low-light handling, and runs a synthetic neutral frame through ONNX Runtime. It does not establish face recall or webcam-specific illumination thresholds.
