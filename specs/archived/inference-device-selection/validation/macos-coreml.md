## Result

- Automatic / CoreML `ALL`: candidate self-test 3.91 ms; candidate and CPU reference both returned `present`; candidate confidence 0.8861; selected provider 1; 30-detection average 2.54 ms.
- Neural Engine preference / `CPUAndNeuralEngine`: candidate self-test 3.22 ms; both sessions returned `present`; confidence 0.8861; selected provider 1; 30-detection average 2.48 ms.
- GPU preference / `CPUAndGPU`: candidate self-test 13.75 ms; both sessions returned `present`; confidence 0.8856; selected provider 1; 30-detection average 2.87 ms.
- All three candidate checks completed below the 125 ms budget. The test harness also forced a candidate self-test mismatch: the host reported `failed`, created a CPU session, and detected the fixture. A forced accelerated runtime error retried that frame on CPU (`selected_provider` sequence 1 then 0); after idle release, the host recreated CPU without retrying CoreML.
- Probe ended with `DetectorHost CoreML probe passed`.

## Automatic enablement

After review of the passing provider, correctness, latency and fallback checks, the coordinator enabled `InferenceDeviceSelection.automaticValidated`. Every real preference session still runs its own validation and falls back to CPU on failure.

## Not checked

- CoreML exposes compute-unit preferences, not proof that every operation physically ran on the named Neural Engine or GPU. These results confirm the requested CoreML provider was attached and the fixture results matched CPU; they do not prove physical unit placement.
- No energy, battery, sustained thermal, camera, camera-timing, UI, or idle-resource measurements were made.
